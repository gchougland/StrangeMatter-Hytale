The Reality Forge remembers the last recipe each player selected at that particular forge. Closing the panel, leaving the world, or restarting the server preserves that choice. Preferences store stable recipe IDs in `machines.json`, separately from the recipe currently being crafted. Up to 64 players' selections are retained per forge; changing a selection refreshes that player's position in the history. An obsolete recipe falls back to the first current recipe. Dismantling a forge removes its preferences with its machine state.

The Resonant Burner holds at most 32,000 remaining fuel ticks (26 minutes 40 seconds). The total includes the item currently burning and every queued item. Its panel shows both amounts, the total capacity, and a fill meter. **Load One** reserves one whole native furnace fuel item. **Load Max** takes as many whole items as fit, scanning the player's backpack, storage and hotbar in their native combined-container order. Items too large for the remaining space are skipped, allowing later smaller fuels to fit. Fuel burns sequentially, preserving each reserved item's duration.

Bulk loading plans all replacements under the native combined inventory's write locks, prepares the machine queue, and publishes one inventory transaction. Slot updates and native inventory-change events see the complete reservation. Every queued item retains its BSON metadata and durability for recovery or dismantling refunds. Old saves that already exceed capacity keep their fuel and cannot accept more until they drain below the limit. Older invalid non-fuel remains available through **Collect Output**; scalar-only legacy fuel continues burning without duplicating it.

Both fuel actions use the existing nonce-scoped, ACK-independent input transport. Recipe navigation still binds the displayed recipe's ID in the same UI packet as its text; a Craft event carrying a previous selection cannot start the newly selected recipe. Animated progress does not replace control bindings.

`MachineControlsVerification.verify(World, MachineService)` is a dedicated helper for the isolated native-server harness. It checks actual machine-save reload and page construction, independent player/forge choices, bounded preference eviction, combined native inventory transactions, full/partial fuel capacity, metadata and durability persistence, failure before inventory mutation, exact sequential burn time, and old-save recovery. It does not claim client rendering or a live multiplayer playtest.
